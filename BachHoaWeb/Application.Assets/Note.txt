2. Giải thích chi tiết nguyên lý "Đường đi và Về"
Mọi hàm trong Repo của bạn (chữ Repo là viết tắt của Repository - Kho chứa dữ liệu) 
đều tuân theo nguyên lý 4 bước cốt lõi sau:

Bước 1: Xin giấy phép và Mở cổng (Mã hóa & Connection)
Nguyên lý: Backend không thể tự tiện thọc tay vào Database (DB). 
Nó cần một cái "chìa khóa" gọi là Connection String (Chuỗi kết nối chứa: Địa chỉ IP máy chủ, tên DB, tài khoản, mật khẩu).

Đường đi trong code: 1. Hàm encrypt.Decrypt(...) giải mã lấy chuỗi kết nối an toàn.
2. using SqlConnection conn = new(...) tạo ra một đường ống dẫn tới DB.
3. await conn.OpenAsync() chính là hành động "mở cửa" đường ống đó ra.

Bước 2: Chuẩn bị xe chở hàng (SqlCommand & Parameters)
Nguyên lý: Có đường ống rồi, bạn cần một "chiếc xe" để chở mệnh lệnh đi. Chiếc xe đó là SqlCommand.

Đường đi trong code:

Nếu là lệnh lấy dữ liệu: Xe chở câu chữ thuần (SELECT * FROM...).

Nếu là lệnh Thêm/Sửa/Xóa: Xe chở tên của Stored Procedure (một hàm viết sẵn dưới DB) 
kèm theo các thùng hàng tham số (@FullName, @Email).

Đoạn code dto.FullName ?? (object)DBNull.Value chính là việc kiểm tra nếu thùng hàng rỗng (null trong C#) thì phải dán nhãn
rỗng của DB (DBNull) để xe qua hải quan SQL Server không bị phạt (báo lỗi).

Bước 3: Thực thi hành động dưới Database
Nguyên lý: Xe chạy xuống DB, bắt DB làm việc. Sẽ có 2 cách DB trả lời:

Cách A (ExecuteReaderAsync): DB trả về một cái bảng danh sách kết quả thô (giống như file Excel). 
Xe chở bảng thô này ngược lên lại Backend.

Cách B (ExecuteNonQueryAsync): Áp dụng khi Xóa. DB không trả về bảng nào cả, 
nó chỉ báo: "Tôi đã xóa thành công 1 dòng rồi nhé!" (Trả về số 1).

Bước 4: Bộ dịch biên phòng (MapReader)
Nguyên lý: Đây là phần quan trọng nhất của lập trình BE kết nối DB. 
Dữ liệu dưới DB truyền lên là dạng các ô dòng/cột thô sơ (reader["FullName"]). 
Ngôn ngữ C# không hiểu trực tiếp kiểu này để làm việc logic được. Nó cần đối tượng (Object).

Đường đi trong code: Hàm MapReader hoạt động như một băng chuyền chạy qua từng dòng của bảng thô. 
Nó bóc cột Id gán vào thuộc tính Id của C#, bóc cột FullName gán vào FullName của C#... 
Quá trình này gọi là ORM (Object-Relational Mapping) tự chế bằng tay.

Bước 5: Đóng gói và Gửi về nơi gọi (DtoResult)
Nguyên lý: Sau khi có được dữ liệu C# sạch sẽ, Repo không trả về trọi lỏi cái List, 
mà bọc nó vào một cái hộp bưu kiện tên là DtoResult.

Trong hộp có:

Succeed = true/false: Để Frontend nhìn vào biết ngay là lệnh chạy lỗi hay chạy thành công.

ResultList hoặc Result: Chứa dữ liệu thật để Frontend lôi ra vẽ lên màn hình cho người dùng xem.

2. Các Hàm Trợ Giúp Nội Bộ (Private Helpers)
Hàm Ánh Xạ Dữ Liệu (MapReader)
C#
        private DtoEmployee MapReader(SqlDataReader reader) => new()
        {
            Id = reader["Id"] as int?,
            FullName = reader["FullName"] as string,
            Email = reader["Email"] as string,
            LoginId = reader["LoginId"] as int?
        };

Ý nghĩa sâu: Hàm này đóng vai trò một "bộ dịch". 
Nó chuyển đổi từng dòng dữ liệu thô (dạng bảng kết quả) từ SQL Server thành một đối tượng C# (DtoEmployee).

Cơ chế hoạt động: Toán tử as thực hiện ép kiểu an toàn (Safe Casting). 
Nếu dữ liệu dưới database là NULL, hệ thống nhận diện từ khóa DBNull.Value và toán tử as sẽ biến nó thành null trong C# 
một cách êm đẹp mà không gây crash ứng dụng.

Hàm Thực Thi Đọc Dữ Liệu Tập Tập Trung (ExecuteReaderAync)
C#
        private async Task<List<DtoEmployee>> ExecuteReaderAync(SqlCommand cmd)
        {
            List<DtoEmployee> result = [];
            var reader = await cmd.ExecuteReaderAsync();
            while (reader.Read())
            {
                result.Add(MapReader(reader));
            }
            return result;
        }

Ý nghĩa sâu: Đây là hàm tối ưu code (bản chất là gom code trùng lặp). Thay vì hàm nào (GetAll, Add, Update) 
cũng phải viết vòng lặp đọc dữ liệu, bạn gom vào đây.

Cơ chế hoạt động: * await cmd.ExecuteReaderAsync() kích hoạt lệnh SQL theo cơ chế bất đồng bộ, 
yêu cầu DB trả về luồng dữ liệu (SqlDataReader).

Vòng lặp while (reader.Read()) duyệt qua từng dòng một từ trên xuống dưới cho đến khi hết dữ liệu. 
Mỗi dòng sẽ được đưa vào hàm MapReader phía trên để đổi thành Object và nạp vào danh sách result.

4. Thao Tác Thêm Mới Dữ Liệu: AddAsync
C#
        public async Task<DtoResult<DtoEmployee>> AddAsync(DtoEmployee dto)
        {
            DtoResult<DtoEmployee> result = new();
            try
            {
                string connStr = encrypt.Decrypt(SQLHelper.ConnString, "truonghoai");
                using SqlConnection conn = new(connStr);
                string sql = "EmployeeAdd";

                using SqlCommand cmd = new(sql, conn);
                cmd.CommandType = CommandType.StoredProcedure;
Ý nghĩa sâu: Điểm khác biệt lớn ở đây là cmd.CommandType = CommandType.StoredProcedure;. Nó báo cho SQL Server biết chuỗi "EmployeeAdd" không phải là câu lệnh văn bản thuần mà là tên của một Stored Procedure đã được định nghĩa sẵn trong cơ sở dữ liệu.

C#
                cmd.Parameters.AddWithValue("@FullName", dto.FullName ?? (object)DBNull.Value);
                cmd.Parameters.AddWithValue("@Email", dto.Email ?? (object)DBNull.Value);
                cmd.Parameters.AddWithValue("@LoginId", dto.LoginId ?? (object)DBNull.Value);
Ý nghĩa sâu: Cơ chế gán tham số an toàn chống tấn công SQL Injection.

Toán tử ?? (object)DBNull.Value giải quyết bài toán: Trong C#, nếu chuỗi hoặc số là null thì truyền thẳng vào SQL Server sẽ bị báo lỗi thiếu tham số. Do đó ta phải chủ động chuyển null của C# thành dữ liệu rỗng của cơ sở dữ liệu (DBNull.Value).

C#
                await conn.OpenAsync();
                var data = await ExecuteReaderAync(cmd);
                result.Result = data.Count > 0 ? data[0] : null;
            }
Ý nghĩa sâu: Procedure EmployeeAdd thường được thiết kế để sau khi INSERT xong sẽ thực hiện một câu lệnh SELECT * FROM Employees WHERE Id = SCOPE_IDENTITY() nhằm trả về chính bản ghi vừa tạo (bao gồm cả cột Id tự tăng tăng từ DB). Bạn đón lấy kết quả đó thông qua ExecuteReaderAync(cmd). Nếu mảng data có dữ liệu, bạn lấy phần tử đầu tiên data[0] gán vào result.Result để trả về cho Client.

5. Thao Tác Cập Nhật: UpdateAsync
C#
        public async Task<DtoResult<DtoEmployee>> UpdateAsync(DtoEmployee dto)
        {
            // ... Mở kết nối tương tự AddAsync ...
                string sql = "EmployeeUpdate";
                using SqlCommand cmd = new(sql, conn);
                cmd.CommandType = CommandType.StoredProcedure;

                cmd.Parameters.AddWithValue("@id", dto.Id ?? (object)DBNull.Value);
                cmd.Parameters.AddWithValue("@FullName", dto.FullName ?? (object)DBNull.Value);
                cmd.Parameters.AddWithValue("@Email", dto.Email ?? (object)DBNull.Value);
                cmd.Parameters.AddWithValue("@LoginId", dto.LoginId ?? (object)DBNull.Value);

                await conn.OpenAsync();
                var data = await ExecuteReaderAync(cmd);
                result.Result = data.Count > 0 ? data[0] : null;
            // ... phần còn lại tương tự AddAsync ...
Ý nghĩa sâu: Hoàn toàn tương tự hành vi của hàm AddAsync, nhưng bổ sung thêm tham số quan trọng bậc nhất là @id để SQL Server biết cần phải cập nhật thông tin cho nhân viên cụ thể nào (WHERE Id = @id). Nó cũng dùng Reader để đón lại dòng dữ liệu mới vừa cập nhật xong nhằm hiển thị lên giao diện.

6. Thao Tác Xóa Dữ Liệu: DeleteAsync
C#
        public async Task<DtoResult<DtoEmployee>> DeleteAsync(object? ID)
        {
            DtoResult<DtoEmployee> result = new();
            try
            {
                if (ID == null)
                    return new() { Succeed = false, Message = "Chưa có ID" };
Ý nghĩa sâu: Kiểm tra phòng ngự (Defensive Programming). 
Nếu lập trình viên gọi hàm xóa nhưng quên truyền ID (bị null), hàm sẽ dừng lập tức và trả về thông báo lỗi, 
tránh việc gửi một yêu cầu vô nghĩa xuống DB làm tốn tài nguyên hệ thống.

C#
                string connStr = encrypt.Decrypt(SQLHelper.ConnString, "truonghoai");
                using SqlConnection conn = new(connStr);
                string sql = "EmployeeDelete";

                using SqlCommand cmd = new(sql, conn);
                cmd.CommandType = CommandType.StoredProcedure;
                cmd.Parameters.AddWithValue("@id", ID);

                await conn.OpenAsync();
                int count = await cmd.ExecuteNonQueryAsync();
                result.Succeed = count > 0;
            }
Ý nghĩa sâu: Tại đây, lệnh thay đổi thành await cmd.ExecuteNonQueryAsync(); thay vì dùng Reader. Hàm này dùng cho các câu lệnh mang tính thực thi hành động (DELETE, UPDATE thuần) mà không cần lấy dòng dữ liệu nào trả về. Nó trả về một số nguyên int biểu thị số dòng bị tác động trong DB. Nếu count > 0 (tức là đã xóa được ít nhất 1 dòng), biến result.Succeed sẽ nhận giá trị true.

C#
        public async Task<DtoResult<DtoEmployee>> DeleteAsync(DtoEmployee dto) => await DeleteAsync(dto.Id);
Ý nghĩa sâu: Đây là một hàm overload (nạp chồng) sử dụng cú pháp Expression-bodied (=>). Nó tạo ra sự tiện lợi cho người lập trình: khi bạn đang cầm nguyên một đối tượng nhân viên dto, bạn chỉ cần gọi DeleteAsync(dto) là nó tự trích xuất dto.Id và chuyển tiếp sang hàm xóa theo ID ở phía trên.
